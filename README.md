# FORMWORK — 建築模型列印工作室

瀏覽器本機運算的建築模型轉換工具。匯入 STL／OBJ，輸出毫米制、Z 軸向上的二進位 STL；模型不傳送到伺服器。

```sh
npm install
npm run dev
npm test
npm run build
```

## 操作

1. 匯入網格，確認原始單位與比例，設定列印平台。無法直接建立實體時會先自動修復網格；可調整接縫容差與補洞上限，或關閉修復查看原始問題。
2. 視需要開啟「只保留外立面」：水平切面填補內部孔洞，封閉小於設定值的開口，保留指定深度的外層細節。
3. 設定噴嘴、壁厚警戒值、懸垂角與支撐尺寸，點「自動加厚、擺放與生成支撐」。
4. 比較修正前後，查看紅色薄牆、橘色懸垂與青色支撐。可以一鍵還原；原始檔不會修改。
5. 匯出模型與支撐的組合 STL、模型單獨 STL 或支撐單獨 STL。分開匯入切片軟體時必須保留共同原點，不要分別自動置中。可另存 JSON 檢查報告。

### 支撐使用另一種材質

在「自動修正」區啟用「支撐使用另一種材質」，填入兩種材質名稱，再生成支撐。選擇「雙材質 3MF」匯出，檔案包含一個組件內的 `Model` 與 `Supports` 兩個獨立部件、不同的基礎材質及共同座標。整組支撐使用第二材質，目前不分開支撐本體與接觸介面。

在切片軟體選擇支援多材質的印表機，將這兩個部件分配到實際耗材槽；通用 3MF 的材質名稱不是印表機專用的噴頭／AMS 設定。支撐以一般幾何部件保存，避免匯入器忽略支撐物件；請使用部件的耗材設定，不是切片器自動支撐的介面耗材設定。若切片軟體未保留材質，可分別匯出兩份 STL，作為同一物件的多個部件匯入並指定耗材，保留相對位置。

雙材質模式允許手動設定 0 mm 接觸間隙，但不會自動設為零，也不會推定材料相容性。請先依耗材廠商與實際機器確認搭配、溫度、層高及清料需求。關閉雙材質模式時，低於 0.05 mm 的間隙恢復為單材質預設 0.2 mm。未生成支撐或材質名稱為空時不能匯出雙材質 3MF；模型與支撐不會在匯出時布林合併。

格式依據：[3MF Core Specification](https://github.com/3MFConsortium/spec_core/blob/master/3MF%20Core%20Specification.md)；匯入流程：[Prusa 多材質模型指南](https://help.prusa3d.com/article/importing-multi-material-model_121191)。尚未做各家切片軟體的匯入相容性與雙材質實印驗證。

## 實作與限制

- Three.js 預覽，Manifold WebAssembly 做實體驗證、布林合併及加厚；運算在 Web Worker，可因參數變更取消。
- 匯入上限 25 MB／500,000 三角面。不讀取 SKP、RVT、IFC、照片或平面圖。
- 匯入網格先嘗試原本的實體建構；失敗的 OBJ 分組一起縫合，避免將材質分組邊界誤判為洞。修復合併容差內的頂點（預設 0.001 mm）、移除重複／退化面、統一面向、分離可判定的邊接觸殼體，並補平面開口。保持內外殼的空腔方向，修復後再由 Manifold 建構驗證，失敗不匯出。
- 補洞上限預設 50 mm，按縮放後開口包圍盒對角線計算；0 為不補洞。每個開口最多 2,048 點，平面偏差容許值為 `max(0.01 mm, 2 × 接縫容差)`。真正分叉、不可定向表面、嵌套輪廓、非平面開口或零厚度平面會回報具體原因；不猜測缺失曲面，不保證修復任意自相交模型。補洞可能封住設計開口，需用「修正前」比較；原輸入保持不變，修復統計列入報告。
- 壁厚以最多 3,000 個三角面中心向內射線估算，並非完整厚度場，可能漏掉局部細節。自動加厚採整體 Minkowski 外擴，會改變外尺寸與縮小孔洞，最多兩輪；上限 20,000 面。修正後重新取樣，保留未解決的警告。
- 自動擺放比較六個軸向，在平台可容納的方向中選擇較少懸垂面積的姿態；不是任意角度全域最佳化。
- 懸垂門檻為表面與水平面的角度。向下表面低於設定值時標示；忽略平台接觸面，未模擬逐層島嶼與橋接能力。
- 支撐由朝下面的面中心與平面網格取樣建立，往下連到平台或模型上表面，保留設定接觸間隙；較高的柱子加寬底部。從支撐幾何扣除模型，避免填滿模型內部。最多 1,200 根／20,000 個平面取樣點，超過會明確回報。柱狀支撐可能側向接觸，並未評估密閉空間可拆除性、支撐自身列印穩定度或完整逐層覆蓋；不是切片器的樹狀支撐引擎。
- 外立面模式保留原始外牆，再以水平分層填補內部（最多 800 層／20,000 面）。外輪廓仍可凹入，並非凸包。窗洞與天井可能被封閉，分層可能產生階梯；大於封口門檻的開口可能仍留下內部空間。實心幾何可由切片器使用稀疏填充，並不等於 100% 材料填充。
- 有風險時需檢閱後才能匯出。輸出不含 G-code 或印表機設定，仍須在切片器確認接觸間隙、層高、支撐拆除及逐層預覽；尚未做實體列印驗證。

## 驗證

`npm test` 驗證 STL 單位／座標軸、無效輸入與關閉修復時的開口拒絕、補洞／接縫／面向／重複面修復、空腔保留、非流形邊分離與不可修復輸入、薄牆加厚、支撐封閉性與接觸間隙、自動方向、外立面填實及凹輪廓保留、底座合併，以及 3MF 封裝、材質分組、共用座標與封閉索引、零間隙支撐不重疊。正式打包使用 `npm run build`。

此環境無 in-app browser，未執行瀏覽器互動與視覺 QA。可選的 WebMCP 比例控制已做 feature detection，但沒有可用的 WebMCP 驗證環境。

幾何引擎：[Manifold](https://manifoldcad.org/docs/jsapi/)。列印參考：[Prusa 建模指南](https://help.prusa3d.com/article/modeling-with-3d-printing-in-mind_164135)。設定值是可調的初始值，不能取代實際噴嘴、材料與冷卻能力的校準。

### 複雜 STL 的近似修復

SketchUp 匯出的 STL 常是三角面湯：`test_modes/test.stl` 有 199,949 面、合併頂點後 11,309 個互不相連的碎塊，只有 3,292 塊本身封閉，另有 4,782 條開放邊、13,730 條三面以上共用邊及 1,147 塊面向不一致。這類網格無法靠平面補洞修復。

匯入後確認單位、擺放方向，先「縮放至平台範圍」，再勾選「近似重建破碎表面」。精確修復失敗時才重建：

1. 以格距 `max(壁厚警戒值 / 2, 使格點不超過 2,400 萬的最小值)` 建立格點，記錄每個格點到最近三角面的距離，不讀取面向或拓樸。
2. 從包圍盒外側灌入「外部」；距任何三角面 `max(格距, 封閉開口寬度 / 2)` 以內的格點會阻擋，接著把外部往回擴張同樣距離（形態學閉運算）。灌不到的格點視為內部並填實。
3. 內部格點與三角面兩側 0.75 格距內為實體，單面牆因此成為約 1.5 格距厚的板，外表面約向外擴張 0.75 格距。以 Manifold level set 產生流形網格並簡化，面數超過 400,000 時放寬簡化誤差，上限為格距。
4. 已封閉、面向一致且最小尺寸小於兩格距的碎塊（窗框、欄杆、玻璃等）不進距離場，原樣聯集回結果，避免被格點吃掉。

「封閉開口寬度」預設 0，只封住約兩格距以下的裂縫；門窗等較寬開口會讓外部灌入，後方空間保持中空，與原始造型一致。要把房間填實，可設定大於門窗寬度的值；封住的開口會留下最深約一半寬度的圓角凹陷，天井與中庭也可能被封閉。原檔不變，格距、封閉寬度、簡化誤差、原樣保留的零件數及原失敗原因寫入檢查報告。

以 1:25 縮放 `test.stl`（約 190 mm）的本機結果：格距 0.44 mm，約 23 秒，輸出約 41 萬面；封閉開口寬度 4 mm 時約 49 秒。舊版無號距離場外殼在同樣比例下格距 1.19 mm，所有房間皆為中空雙層牆。
